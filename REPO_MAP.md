# Карта репозитория (Repository Map)

В этом файле описана архитектура проекта, ключевые механизмы и структура папок.
**Цель документа:** помочь будущим ИИ-агентам и разработчикам быстро ориентироваться в кодовой базе, не дублировать функционал и соблюдать установленные паттерны проектирования.

## 🏗 Ключевые архитектурные решения

1. **Тип плагина:** 
   Немодальное окно (WPF), запускаемое через `IExternalCommand` (`MainCommand.cs`). Привязывается к главному окну Revit через `WindowInteropHelper`, чтобы не перекрываться другими приложениями и не блокировать интерфейс Revit.
2. **Многопоточность (Thread Bridging) — КРИТИЧЕСКИ ВАЖНО:**
   Запросы к LLM (HTTP) и UI работают в фоновых/UI потоках. Доступ к Revit API из них **запрещен**. 
   Для взаимодействия с Revit используется `RevitTaskHandler` (реализует `IExternalEventHandler`). Любой код, обращающийся к `Document` или элементам, **обязан** оборачиваться в `MainCommand.TaskHandler.ExecuteAsync(...)`.
3. **Интеграция с LLM (DeepSeek / OpenAI):**
   Реализована через встроенный `HttpClient` с поддержкой **SSE (Server-Sent Events)** для потокового вывода ответа (Streaming). Парсинг JSON идет через `JavaScriptSerializer` (без сторонних библиотек вроде Newtonsoft.Json, чтобы сборка оставалась чистой). Поддерживается параметр `"thinking"` для моделей с цепочкой размышлений (DeepSeek-R1 / Flash).
4. **Инфраструктура Skills (Function Calling):**
   Основана на интерфейсе `IRevitSkill`. Навыки сами отдают свою JSON-схему (для отправки в LLM) и сами себя выполняют.
   * **Hard Skills:** Встроенные навыки, скомпилированные в плагин (например, чтение параметров).
   * **Soft Skills (Динамические):** Навыки, которые агент может создавать для себя сам по запросу пользователя. Пишутся на C# (CodeDom, синтаксис 5.0), сохраняются в виде `.json` файлов в `%AppData%\RevitAIClient\SoftSkills` и компилируются в памяти (Runtime). Агент может обновлять их код и исправлять ошибки компиляции.
5. **Безопасность (Human-in-the-loop):**
   Навыки, которые изменяют модель, имеют флаг `RequiresConfirmation = true` (динамические Soft Skills имеют его **всегда**). Оркестратор в UI (`ChatWindow.xaml.cs`) перехватывает их вызов и запрашивает подтверждение пользователя перед выполнением транзакции или выполнением сгенерированного кода.
6. **Хранение состояния:**
   Контекст беседы (`history.json`) и API-ключ (`apikey.txt`) сохраняются локально в `%AppData%\RevitAIClient`.
   В UI добавлен переключатель **"Send Context"**. Если он выключен, для экономии токенов отправляется только новый запрос и системный промпт. Если включен — отправляется вся история текущего чата (критично для итеративного создания Soft Skills).

## 📁 Структура проекта (`src/RevitAIClient/`)

### 1. Root
* `RevitAIClient.csproj` — Файл проекта (.NET 4.8). Настроен на исключение копирования локальных Revit DLL (`<Private>False</Private>`).
* `RevitAIClient.addin` — Манифест плагина для загрузки в Revit.

### 2. Commands/
Отвечает за инициализацию плагина и связь с ядром Revit.
* `MainCommand.cs` — Точка входа (`IExternalCommand`). Создает UI и регистрирует `TaskHandler`.
* `RevitTaskHandler.cs` — Мост потоков (`IExternalEventHandler`). Обрабатывает очередь делегатов в основном потоке Revit.

### 3. LLM/
Отвечает за связь с нейросетью.
* `ILLMProvider.cs` — Базовый интерфейс.
* `OpenAIProvider.cs` — Реализация HTTP-клиента. Парсит SSE-стрим, собирает `tool_calls`.
* `ChatMessage.cs` / `ToolSchema.cs` — POCO-классы для сериализации/десериализации JSON.

### 4. Skills/
Инструменты для LLM.
* `IRevitSkill.cs` — Базовый интерфейс.
* **Встроенные (Hard) навыки:**
  * `GetActiveViewSkill.cs` — (Read-Only) Получает информацию о текущем виде.
  * `GetElementParametersSkill.cs` — (Read-Only) Читает все параметры элемента по ID.
  * `SetElementParameterSkill.cs` — (Write) Изменяет параметр. Требует подтверждения.
  * `UpdateCategoryParamInActiveViewSkill.cs` — (Write) Массовое изменение. Требует подтверждения.
* **Управление динамическими (Soft) навыками:**
  * `CreateOrUpdateSoftSkillSkill.cs` — Позволяет LLM генерировать C# код и сохранять новый навык.
  * `GetSoftSkillCodeSkill.cs` — Позволяет LLM читать исходный код существующего Soft-навыка для анализа.
* **Папка `Dynamic/`**:
  * `SoftSkillDefinition.cs` / `SoftSkillManager.cs` — Структура и менеджер сохранения навыков в `%AppData%`.
  * `DynamicSkillCompiler.cs` — Компилятор C# кода в памяти (на базе `CSharpCodeProvider`).
  * `DynamicSkillAdapter.cs` — Обертка, превращающая динамический код в `IRevitSkill`.

### 5. UI/
Пользовательский интерфейс и оркестрация.
* `ChatWindow.xaml` — Разметка окна. Современный Fluent-дизайн. Содержит панель чата, настройки (Thinking, Effort) и боковую панель со списком доступных навыков (Available Skills).
* `ChatWindow.xaml.cs` — Code-behind. Здесь:
  - Регистрируются навыки (`_skills.Add(...)`) и обновляются через `OnSkillUpdated`.
  - Управляется история сообщений и логика переключателей (Send Context, Debug Logs).
  - Находится оркестратор (цикл "Запрос -> Ответ -> Вызов функции -> Запрос подтверждения -> Возврат результата -> Окончательный ответ").

## 🚀 Инструкция для ИИ-агентов (Как добавить новый функционал)

1. **Создание нового встроенного навыка (Hard Skill):**
   - Создайте новый класс в папке `Skills/`.
   - Реализуйте интерфейс `IRevitSkill`.
   - Если навык меняет данные в Revit, установите `RequiresConfirmation => true;`.
   - Зарегистрируйте навык в `InitializeSkills()` в `ChatWindow.xaml.cs`.
   
2. **Создание динамического навыка (Soft Skill):**
   - Soft Skills создаются самим агентом во время работы плагина (через вызов `CreateOrUpdateSoftSkillSkill`). Не пишите файлы `.json` вручную в репозитории.
   - Синтаксис кода в Soft Skills ограничен C# 5.0.

3. **Зависимости:**
   - **Не устанавливайте** тяжелые NuGet-пакеты без явного разрешения пользователя. Проект спроектирован так, чтобы собираться в одну чистую DLL. Используйте встроенные средства .NET 4.8.

4. **Логирование:**
   - Для вывода системной информации в UI используйте метод `LogDebug(...)` в `ChatWindow.xaml.cs`. Сообщения будут видны, если в UI активирован чекбокс **"Debug Logs"**.
